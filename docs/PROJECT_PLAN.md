# SourceGate 项目方案

## 项目目标

为 CAPEX、数据中心基础设施、LLE 及 EPC 采购建立可追溯的供应商准入流程。把供应商“自报信息”转化为“有证据、按统一政策计算、由授权人审批”的准入记录。首个品类建议选择冷却系统或电力设备，避免初期混用制造商、代理商、EPC 的不同业务模型。

## 判定原则

1. 规则版本独立于供应商，供应商不可自行选择分数。申报事实经证据核实后进入规则引擎。
2. 内容完整性、签署身份授权、事实真实性分别记录。有效签名不代替事实核查。
3. 六维独立基准线；高分不能抵消已确认红线或关键能力缺口。
4. 未知和失败分开：资料待核验时输出待核验，不以缺失资料直接认定造假。
5. AI 可提取候选字段、建议澄清并引用页码；不得自己确认真实性、覆盖核验状态、修改规则或批准入库。
6. 更改资料或政策必须重签和复算。所有决定保留政策、证据版本、理由和批准人。

## 工作流与责任

| 阶段 | 责任角色 | 输入与检查 | 退出条件 |
|---|---|---|---|
| 模板批准 | 采购负责人、品类、财务、技术、ESG | 适用品类、地区、指标阈值、权重、红线 | 发布政策版本 |
| 申请填写 | 供应商授权代表 | 公司与注册号、三年财务、六维事实、支持文件 | 必填完成 |
| 签署 | 供应商授权代表 | 申报快照、附件摘要、政策版本、唯一随机数与时间 | 受信签署完成 |
| 完整性检查 | 系统 | 签名、哈希、重复申请、过期及版本冲突 | 无完整性错误 |
| 身份及真实性核验 | 采购、财务、技术、ESG/质量审核人 | 注册机关、发证方、审计师、客户、现场审核 | 出处、核验人、时间和覆盖范围明确 |
| 评分与澄清 | 规则引擎、相关评审人 | 固定规则计分；缺口、矛盾、异常 | 关键澄清关闭且指标获确认 |
| 决策审批 | 授权采购负责人 | 原始精度分数、基准线、红线、范围和条件 | 审批完成 |
| 入库与复审 | 主数据管理员、品类负责人 | 审批记录、品类/地区范围、有效期、复审计划 | ERP 入库且安排复审 |

原型以单浏览器演示上述角色操作，未实现真正账户隔离。正式应用必须由后端强制供应商只能访问自身申请；审核人只能访问授权维度；审批人不得由供应商或同一评审身份冒用。

## 真实性核验方案

| 对象 | 要求与方法 | 未验证时 |
|---|---|---|
| 企业主体 | 企业注册机关登记、名称、注册号、存续状态一致 | 暂停准入 |
| 签署人 | 身份证明、企业授权函、授权期限、职位范围；必要时公司独立渠道回拨 | 暂停准入 |
| 财务 | 连续三个完整财年、相同法人/合并口径、审计签发方、审计意见和持续经营事项 | 财务澄清 |
| 市场份额 | 第三方报告、统计范围、年份和市场规模分母；交叉比对出货/销售 | 不采信自报份额 |
| 证书与报告 | 发证机构独立查询、编号、主体、场址、范围、有效期 | 不确认该证据 |
| 履约指标 | 合同、出货、FAT、验收及 NCR/CAPA 台账对账，避免只选有利样本 | 纠正统计口径 |
| ESG | 文件、执行记录、事件及整改；重大违规需独立确认 | 形成澄清；确认严重问题再触发红线 |

## 核心记录

Supplier、Application、AnnualFinancial、PolicyVersion、CriterionDefinition、EvidenceVersion、Attestation、Verification、Clarification、ScoreResult、Approval、AuditEvent。每项事实最终应关联具体文件、页码/字段、发证主体和核验记录。原型以一个完整维度证据包覆盖该维度三项指标；生产应升级为逐指标证据映射。

建议生产 API：申请创建与更新、证据预签名上传与扫描、签署挑战、外部电子签回调验证、独立核验、规则试算、澄清回复与关闭、审批和 ERP 同步。所有审批在服务端重新计算结果，不接受客户端传入的 verified=true 或最终分数。

## 生产前控制

- 受信密钥登记、撤销、轮换与身份绑定；签署挑战单次使用、过期控制、重放检测、可靠时间戳。
- 文件恶意内容扫描、MIME/大小验证、静态加密、最小权限下载、访问日志与数据保留策略。
- 政策由授权管理员发布且不可覆写；历史申请固定到政策版本，重新评审另建版本。
- 逐指标证据、发证机构和证书有效期；拒绝将一个 ISO 证书视为所有质量绩效的证明。
- 不可变服务器审计、外部时间戳或受保护日志归档；审计、财务等敏感数据按角色限制。
- 技术关键规格、强制许可证、严重劳动/安全事项设硬门槛，不能仅按平均符合率放行。
- 新企业、代理商、无市场份额数据及无到期 CAPA 的情况，发布专门品类模板或走有依据的例外审批；不得临时删指标并重新归一化抬高分数。
- 有条件准入必须有整改责任人、期限、限额和复审；逾期暂停新的采购资格。

## 分阶段计划（建议估计，非承诺）

| 阶段 | 主要成果 | 验收方式 |
|---|---|---|
| 当前 | 可交互 App、18 项规则、签署/哈希、人工核验及澄清、deck | 功能演示和规则边界测试 |
| 政策试点 | 单品类模板、历史案例回测、财务/ESG/技术负责人批准 | 10–20 家脱敏历史样本比对人工结论 |
| 企业 MVP | 后端、登录角色、文件安全、受信签署、审计与邮件草稿 | 多角色权限、并发修改、篡改/重放及过期场景测试 |
| 核验集成 | 企业登记、发证方、电子签、OCR/AI 候选事实 | 对照真实出处，核查误报、漏报和人工工作量 |
| 入库集成 | ERP、供应商分层、资格有效期与复审 | 审批后单次入库，撤销/过期及时停止新采购 |

衡量指标建议：平均完成周期、人工核验工时、资料一次完整率、未解决澄清数量、人工结论一致率、误放行、误拒绝、复审逾期率。不在无真实样本时宣称准确率或节省比例。
